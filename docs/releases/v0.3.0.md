**Windows:** installed apps update themselves to this version, and the server at home follows them, applying its new migration. Everyone logs in once more after the update. To install from scratch, download `APC-Universal-Repair-Setup-0.3.0.exe`, or the portable exe to run without installing.

### What's new
- **Sessions the server checks:** a login or sign-up starts a session, and the app sends its token on every call. Every route but the health check, the login and the sign-up refuses a call without one. The database keeps only the token's hash.
  - A session lasts 7 days from its last use and ends on "Sair". When it expires, the app goes back to the login and says so.
  - Photos load at paths signed for the session.
  - On the phone, the session is kept in the keychain.
- **Fewer login attempts:** 5 wrong passwords for a username lock it from that address for 15 minutes, and an address gets 30 logins and 10 sign-ups every 15 minutes. Past that, the login and the sign-up say how many minutes to wait.
- **Only this computer's addresses:** the server answers only requests addressed to it (localhost, its own IPs, and names in `APC_ALLOWED_HOSTS`). That shuts out web pages that reach it through DNS rebinding.
- **SQLite or PostgreSQL:** the server can keep its data in a SQLite file, with nothing to install, or in PostgreSQL, as `DATABASE_URL` says. Without one, it uses the SQLite file.
  - The installer asks which, on its new *Banco de dados* page, explaining each.
  - `pnpm --filter @apc/api db:copy` moves the data from one database to the other.
  - The guide has the steps in "Switching databases".
  - A server already on PostgreSQL keeps it: its `.env` names it.

**Windows:** os apps instalados se atualizam sozinhos para esta versão, e o servidor em casa os acompanha, aplicando a migração nova. Todo mundo entra de novo uma vez depois da atualização. Para instalar do zero, baixe o `APC-Universal-Repair-Setup-0.3.0.exe`, ou o exe portátil para rodar sem instalar.

### Novidades
- **Sessões conferidas pelo servidor:** um login ou cadastro abre uma sessão, e o app envia o token dela em toda chamada. Toda rota, menos o health check, o login e o cadastro, recusa uma chamada sem ele. O banco guarda só o hash do token.
  - Uma sessão dura 7 dias desde o último uso e termina no "Sair". Quando ela expira, o app volta para o login e avisa.
  - As fotos carregam por caminhos assinados para a sessão.
  - No celular, a sessão fica no keychain.
- **Menos tentativas de login:** 5 senhas erradas para um usuário o bloqueiam a partir daquele endereço por 15 minutos, e um endereço tem 30 logins e 10 cadastros a cada 15 minutos. Passando disso, o login e o cadastro dizem quantos minutos esperar.
- **Só os endereços deste computador:** o servidor só responde a requisições endereçadas a ele (localhost, os IPs dele e os nomes do `APC_ALLOWED_HOSTS`). Isso barra páginas da web que chegariam a ele por DNS rebinding.
- **SQLite ou PostgreSQL:** o servidor pode guardar os dados num arquivo SQLite, sem nada para instalar, ou no PostgreSQL, como o `DATABASE_URL` disser. Sem ele, usa o arquivo SQLite.
  - O instalador pergunta qual, na página nova *Banco de dados*, explicando cada um.
  - O `pnpm --filter @apc/api db:copy` passa os dados de um banco para o outro.
  - O guia tem os passos em "Trocar de banco de dados".
  - Um servidor que já usa o PostgreSQL continua nele: o `.env` dele o indica.

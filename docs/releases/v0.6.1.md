**Windows:** installed apps update themselves to this version. To install from scratch, download `APC-Universal-Repair-Setup-0.6.1.exe`, or the portable exe to run without installing.

### Before updating
- **Have the database's recovery copy at hand.**
  - Versions v0.4.2 to v0.6.0 could drop the SQLite key from `config.json` the first time the window was closed to the tray. The next start then made a new key that doesn't open the data, and the window said *The SQLite file … doesn't open with its key*.
  - This version asks for the recovery copy instead, the one the app showed on its first start, and opens the same data with it.
  - Without that copy the data can't be opened. Leave `data\apc.db` where it is.
  - See [the home server guide](https://github.com/ChrisCamilo/apc-universal-repair/blob/main/docs/home-server.md#11-the-datas-key-doesnt-open-it).

### What's new
- **The database key is kept** (#277):
  - `config.json` is always changed from the file as it is, so the key is no longer lost when the window goes to the tray;
  - the app never makes a new key for data that already has one;
  - when the key is missing or doesn't open the data, *O servidor não ligou* asks for the *Chave de recuperação*, checks it opens the data, keeps it and opens the app on the same data. A recovery copy that doesn't open the data is refused, and nothing changes.
- **A taken port is named** (#255):
  - when another program holds the server's port (3000), the window says which program and its process, instead of trying again and failing;
  - *Usar outra porta* opens *Servidor e banco de dados* on its new *Porta do servidor* field, from 1024 to 65535. It warns that the phone's address changes with it, checks the port is free and moves the server there. The port is kept for the next starts;
  - the tray's menu says when the server is off.
- **A clearer failure screen:**
  - *O servidor não ligou* now covers the whole window, instead of showing the screen under it through it;
  - it names the server's last error even when it comes just as the server stops, as with a PostgreSQL that is off.

**Windows:** os apps instalados se atualizam sozinhos para esta versão. Para instalar do zero, baixe o `APC-Universal-Repair-Setup-0.6.1.exe`, ou o exe portátil para rodar sem instalar.

### Antes de atualizar
- **Tenha à mão a cópia de recuperação do banco.**
  - As versões v0.4.2 a v0.6.0 podiam tirar a chave do SQLite do `config.json` na primeira vez que a janela ia para a bandeja. A abertura seguinte criava uma chave nova, que não abre os dados, e a janela dizia *The SQLite file … doesn't open with its key*.
  - Esta versão pede a cópia de recuperação no lugar disso, a que o app mostrou na primeira abertura, e abre os mesmos dados com ela.
  - Sem essa cópia os dados não abrem. Deixe o `data\apc.db` onde está.
  - Veja o [guia do servidor em casa](https://github.com/ChrisCamilo/apc-universal-repair/blob/main/docs/home-server.md#11-a-chave-dos-dados-não-os-abre).

### Novidades
- **A chave do banco é mantida** (#277):
  - o `config.json` é sempre alterado a partir do arquivo como ele está, então a chave não se perde mais quando a janela vai para a bandeja;
  - o app nunca cria uma chave nova para dados que já têm uma;
  - quando a chave falta ou não abre os dados, o *O servidor não ligou* pede a *Chave de recuperação*, confere se ela abre os dados, guarda-a e abre o app nos mesmos dados. Uma cópia que não abre os dados é recusada, e nada muda.
- **Uma porta ocupada é identificada** (#255):
  - quando outro programa ocupa a porta do servidor (3000), a janela diz qual programa e o processo dele, em vez de tentar de novo e falhar;
  - o *Usar outra porta* abre o *Servidor e banco de dados* no novo campo *Porta do servidor*, de 1024 a 65535. Ele avisa que o endereço do celular muda junto, confere se a porta está livre e passa o servidor para ela. A porta fica guardada para as próximas aberturas;
  - o menu da bandeja diz quando o servidor está desligado.
- **Uma tela de falha mais clara:**
  - o *O servidor não ligou* agora cobre a janela inteira, em vez de deixar ver a tela de baixo através dele;
  - ele mostra o último erro do servidor mesmo quando o erro chega bem na hora em que o servidor para, como com um PostgreSQL desligado.
